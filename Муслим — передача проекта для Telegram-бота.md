## 4. Роли (apps/users/models.py → `User.Role`)

| Роль | Код | Что может |
|---|---|---|
| Программист | `programmer` | всё |
| Шеф | `chef` | всё кафе, отчёт 45 дней, настройки |
| Админ | `admin` | заказы, меню, столы, отчёт за день; доставку и самовывоз подтверждает он |
| Повар | `cook` | видит подтверждённые заказы: «Готовится», «Готов»; стоп-лист |
| Официант | `waiter` | заказы со столов (в кафе / с собой), «Беру стол», «Подан на стол», вызовы, «Освободить стол» |
| Курьер | `courier` | доставки после подтверждения: «Беру заказ», «В пути», «Доставлен» |

Свойства: `is_programmer`, `is_chef` (шеф+программист), `is_cafe_admin` (админ+шеф+программист), `is_cook`, `is_waiter`, `is_courier`. У сотрудника есть поле **`telegram_id`** (уникальное, может быть пустым) — для кнопок в Telegram.

## 5. Заказы (apps/orders)

- Виды `Order.Kind`: `hall` «В кафе» (зелёный), `takeaway` «С собой» (жёлтый), `delivery` «Доставка» (красный), `pickup` «Самовывоз» (оранжевый). Поле `source`: `site` / `bot`.
- Статусы: `new` → `accepted` → `cooking` → `ready` → (`on_the_way` для доставки) → `completed`; `cancelled`.
- **Вся логика статусов — `apps/orders/status_service.py`**: таблица `ACTIONS` (accept, reject, cook, ready, send, complete, cancel), `available_actions(order, user)`, `change_status(order, action, user, reason)`, `claim_order(order, user)` («Беру стол» / «Беру заказ»), `close_visits(table, user)` («Освободить стол»). **Бот должен вызывать эти же функции**, а не менять статус напрямую — тогда права и история работают одинаково.
- Доверенный телефон: после подтверждения официантом следующие заказы с этого телефона за этим столом сразу «Принят» (до «Освободить стол» или 4 часов).
- Заказ создаётся `POST /api/orders/` (без входа). Статус гостю — `GET /api/orders/<public_id>/`.

## 6. API (основное)

- Вход: `POST /api/auth/login/` (email или логин + пароль, `remember`), `POST /api/auth/refresh/`, `GET /api/auth/me/`.
- Гость: `GET /api/menu/`, `GET /api/cafe/`, `GET /api/tables/<token>/`, `POST /api/orders/`, `GET /api/orders/<uuid>/`, `POST /api/table-calls/`.
- Сотрудники: `GET /api/staff/orders/?active=true`, `POST /api/staff/orders/<id>/claim/`, `POST /api/staff/orders/<id>/status/ {"action","reason"}`, `/api/staff/table-calls/` (+ `/<id>/done/`), `GET /api/staff/tables/`, `POST /api/staff/tables/<id>/close-visit/`.
- Админ: `/api/admin/categories|dishes|sizes|extras|tables|staff|cafe/`, отчёты `/api/admin/reports/day/`, `/period/`, `/periods/` (+ `pdf/`).
- Swagger: `/api/docs/`.

## 8. Telegram-бот — утверждённый план

**Библиотека:** aiogram 3 (последняя 3.x; на 28.10.2026 по документации это 3.31). Версию закрепить в `requirements.txt` точно (`aiogram==3.x.y`), проверив на PyPI в день установки.

**Одна база с сайтом — главное правило.** Бот живёт **внутри этого же Django-проекта** (новое приложение `apps/bot/`), читает и пишет ту же SQLite через Django ORM (`sync_to_async`). Не через HTTP-API. Поэтому меню, стоп-лист, столы, настройки, заказы — всегда одинаковые на сайте и в боте. Все смены статусов — **только через `apps/orders/status_service.py`** (те же права и история).

**Запуск:** отдельный systemd-сервис `muslim-bot` (`python manage.py runbot`), режим **polling** (HTTPS пока нет). `BOT_TOKEN`, ID группы и ID тем — только в `.env`.

**Как сайт сообщает боту (синхронизация):** «почтовый ящик» (outbox) — таблица событий в базе. Когда на сайте создан заказ / сменился статус / вызов официанта, в той же транзакции пишется событие. Бот раз в 1–2 с забирает новые события и отправляет / **редактирует** сообщения. Если Telegram недоступен — сайт работает, события дождутся. У заказа хранится, какие сообщения в Telegram ему принадлежат (чтобы редактировать одно сообщение, а не слать новые).

**Сотрудники — одна группа «Муслим — смена» с темами (форум):**
- «Админы» — новые доставки и самовывозы: Подтвердить / Отклонить (с причиной); итог по каждому заказу.
- «Кухня» — подтверждённые заказы с составом: Готовится / Готов.
- «Зал» — заказы со столов (в кафе / с собой): Беру стол / Подтвердить / Отклонить / Подан на стол; вызовы «Позвать официанта», «Счёт» с кнопкой «Выполнено»; «Освободить стол».
- «Доставка» — после подтверждения: Беру заказ / В пути / Доставлен; адрес, телефон, оплата, сдача.
- «Отчёты» — отчёт за день в конце смены (переключатель «Отчёт в группу» в настройках сайта).
- Кнопку может нажать только сотрудник с привязанным Telegram и нужной ролью (проверка через `available_actions`). Чужим — всплывающее «Нет прав». Всё, что нажали в боте, сразу видно на сайте, и наоборот.
- Цвета/значки видов заказа: 🟢 в кафе, 🟡 с собой, 🔴 доставка, 🟠 самовывоз.

**Привязка сотрудника:** в панели (раздел сотрудника / профиль) кнопка «Привязать Telegram» → одноразовая ссылка `t.me/<бот>?start=link_<код>` (живёт ~10 минут). Сотрудник открывает — бот записывает его `telegram_id` в `User.telegram_id`. Отвязать — кнопкой в панели. Заблокированный сотрудник кнопками пользоваться не может.

**Гости заказывают в боте (кнопки в чате):** /start → категории → блюда (фото, цена, размеры, добавки) → корзина → «Доставка» или «Самовывоз» → телефон кнопкой «Поделиться контактом» → имя → адрес (для доставки) → оплата → подтверждение. Заказ создаётся с `source="bot"` теми же проверками, что и на сайте (мин. сумма, кафе открыто, стоп-лист, цены считает сервер). Гостю бот сам присылает смену статуса и причину отмены; команда «Мои заказы». Заказы «в кафе / с собой» — только по QR на сайте. Позже, когда будет домен и HTTPS, добавить Mini App (наш сайт внутри Telegram).

**Порядок работы (по шагам, каждый — с тестами):**
1. Модели: outbox-события, сообщения заказа в Telegram, коды привязки; миграции.
2. Запись событий на сайте (создание заказа, статусы, вызовы, освобождение стола).
3. Бот: запуск, привязка сотрудника, отправка и редактирование сообщений в темах, кнопки статусов.
4. Заказ гостем через бота + уведомления гостю.
5. Отчёт за день в «Отчёты». 6. systemd-сервис на сервере, инструкция.
