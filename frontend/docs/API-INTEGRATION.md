# Подключение Swagger API

Адрес API: http://172.20.10.4:8000/api/ . Документация: http://172.20.10.4:8000/api/docs/ . Схема OpenAPI проверена 26 октября 2026 года: 45 путей, изменений относительно ранее сохранённой схемы нет.

## Запуск

`npm start` — http://localhost:4174/admin . Гостевое меню: http://localhost:4174/ . API включён по умолчанию. Локальный сервер пересылает /backend/api/ и /backend/media/ на фиксированный адрес API, поэтому браузеру не требуется CORS-доступ к другому адресу.

Для другого сервера задайте MUSLIM_API_ORIGIN перед запуском. Для другого порта используйте PORT. `npm run start:demo` запускает вариант без API. Для возврата к демо в обычной версии нажмите «Открыть демо-панель» на экране входа.

Опубликованная статическая версия остаётся доступной по прежнему адресу. Кнопка «Открыть с API» ведёт в локальную версию. Чтобы соединить именно опубликованный сайт с API без локального запуска, понадобится доступный серверный HTTPS-адрес или настроенное приватное соединение: локальный HTTP-адрес нельзя напрямую использовать из опубликованной HTTPS-страницы.

## Подключённые операции

- Вход JWT, получение текущего пользователя, автоматическое обновление токена и повторный вход после истечения сессии. Токены сохраняются только на время вкладки и привязаны к настроенному API. Пароль не сохраняется.
- Категории, блюда, размеры и добавки загружаются с сервера. Редактор сохраняет блюдо, размеры и фото; частичные ошибки показываются явно. Наличие для повара переключается специальным методом API.
- Столы, QR PNG и PDF, пользователи, назначаемые роли, журнал смен ролей, параметры кафе.
- Заказы сотрудников, доступные действия с учётом роли, отдельный метод «Беру стол», отмена с причиной и вызовы официанта.
- Гостевое меню, серверные ID размеров и добавок, заказ по QR-токену, доставка и самовывоз, наличная оплата или карта при получении, серверный статус и обновление статуса.
- В запрос заказа не передаются цены и итоговая сумма: их рассчитывает API. Сетевой сбой не вызывает автоматическую повторную отправку заказа.

## Проверка

`npm run check` — проверка синтаксиса. `npm test` — 13 тестов: сохранение демо-данных, преобразование каталога, создание тела заказа без цен, обновление сессии, отсутствие повторного POST при сетевой ошибке, маршрут claim, проверка формата скачиваемых файлов, пересылка JWT/JSON/multipart и ошибки соединения.

Подробные результаты живой проверки находятся в API-VALIDATION.md.
